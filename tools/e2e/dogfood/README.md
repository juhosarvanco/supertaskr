# Explicit private provenance

Run from the selected PRODUCT checkout through
`node tools/e2e/scripts/private-dogfood.mjs e2e --product <product> --at <full revision>`.
The entry validates the exact product origin/revision and its split binding before
any RECORDS read. Ordinary Playwright discovery uses tests/ and never loads this
directory. Parser/app provenance have matching separate configurations; the three
archived native capture cases require the test-only private-dogfood Cargo feature.

This suite retains actual board parse, ruling/INDEX, standing-read size, original
record-name floors, selected private prose rename scans, advisory corpus reporting,
private creation-law prose, switch-inventory/profile correspondence, tier-budget
ruling, checkpoint template, grant/keep-awake policy, merge policy, hook metadata,
historical CLI attribution/card claims and seat-pack command provenance.
Authored ordinary controls retain scanner, grammar, protocol, byte accounting,
positive/negative guard and rendering behavior independently of those records.

Neither discovery separation nor an ordinary green establishes private provenance.
Permanent selected-context runs remain required after migration. The method-eval
private-policy producer, historical range-policy origins and native committed graph producer/check routes remain
explicit unfinished obligations: their named private-dogfood commands refuse until
those configured routes exist, rather than reading stale product records.
