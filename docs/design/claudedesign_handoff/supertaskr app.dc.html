Symbols live in the panel, never on the canvas — the graph would double in size and stop being a map. Visibility in the left gutter, kind and reference count on the right, imports last with the component they resolve to. Rows are not clickable in v1; they open the editor in v2.
layout · deterministic, and why nothing moves
1Column = longest path from any root along declared edges only. Observed-only (drift) edges never move a node — otherwise an accidental import would rearrange the map.
2Cycles: break at the edge whose target has the lowest component id, mark it drift-neutral, keep drawing. A cycle is a finding, not a crash.
3Row order within a column: by component id, ascending. Not by crossing count — a two-pass crossing minimiser reshuffles rows every time a component is added, and stability beats tidiness here.
4Rows are slots of 150px (T0) — a new component appends to the bottom of its column and nothing above it moves. Ids are assigned once and never reused, so “append” is permanent.
5Pins win: a pinned node keeps its dropped position and is skipped by slot assignment; its computed slot stays empty and ghosted rather than collapsing.
6Edges route as elbows with a 12px stub off the node edge, mid-gap vertical, 12px stub in. Same-column edges bow below the row band. No curves — an orthogonal route is legible at any zoom and cheap to hit-test.
7Re-index recomputes columns; if a component's column changes, it moves — that is a real structural change and worth seeing. Everything else is frozen between indexes.
T0 slot 150px · T1 container grows down into the slots below it in its own column and pushes only that column · zoom is scale, never re-layout
That closes the five gaps: overlays, T2, layout rules, search and pinning, and neighbourhood hover. Every state in the handoff now has a treatment, and the layout section is the one a coding session will lean on hardest — it is deliberately dumber than a graph library would be, in exchange for a map that never rearranges itself while you are looking at it.
