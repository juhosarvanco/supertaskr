## Acceptance criteria
- THE cargo suite SHALL gain an ACL-surface regression test built on
  the T-007 verifier's demonstrated machinery (resolved authority
  from shipped artifacts + real InvokeRequests): dialog/fs/opener
  commands denied, app commands allowed, remote origins denied —
  the zero-webview-surface proof pinned, not re-derived per task.
- THE pick_project_folder command SHALL be single-flight (AtomicBool;
  concurrent invocations get a typed busy result) and the
  validate→arm mutex window SHALL be narrowed per the T-007
  verifier's residual notes.
- IF the ACL surface changes in any future diff THEN this test SHALL
  fail with a diff of the grant set (the alarm F-04 needs).

**Criterion 2a — single-flight picker** (absorbs T-007-s3).
`WatchState` gains `picking: Arc<AtomicBool>`;
`WatchState::begin_pick()` compare_exchanges it and returns
`Option<PickInFlight>` — an RAII guard whose Drop releases the latch on
every path, panic included. The `pick_project_folder` command (lib.rs)
claims the guard BEFORE opening the native dialog; refusal is the new
TYPED `PickOutcome::Busy` (wire shape `{"kind":"busy"}`, pinned by
test), so a double-click race or a compromised webview can never stack
native dialogs — the T-007 verifier's observation (1).
`apply_picked_folder` now CONSUMES a `PickInFlight` (signature change),
making "the validate→arm→commit pipeline runs under the latch"
structural — no unguarded caller can exist. The guard travels into the
spawn_blocking task, so it is held from pre-dialog to post-commit.

**Criterion 2b — validate→arm mutex window narrowed** (the T-007
verifier's residual note (2), implemented as named). Pre-T-021,
`apply_picked_folder` held the project mutex across canonicalize →
validate → re-arm rendezvous (up to `REARM_TIMEOUT` = 10s) → commit, so
a concurrent `docs_snapshot` blocked behind a slow re-arm. Now the
mutex is taken for the COMMIT alone (`*state.project.lock() =
Some(..)`, one statement); the rendezvous runs lockless. Soundness
argument, recorded: (a) picks cannot interleave with picks — the flight
guard serializes the whole pipeline (that is why 2a and 2b are one
criterion: the narrowing is safe BECAUSE of the guard); (b) the
validate→arm TOCTOU window was never protected by the mutex — the
watcher thread's own `has_plain_docs_dir` gate re-checks at arm time
(T-007's defense in depth, verifier-attacked then); (c) seq ordering
across the switch is unchanged: ack → commit → seq, exactly the old
sequence, so the pick snapshot still outranks every pre-pick emit and
the reset-baseline invariant ("snapshot never older than baseline") is
untouched.
Also implemented from the residual notes, declared: observation (4) —
the rendezvous `recv_timeout` now distinguishes `Timeout` ("watcher
re-arm timed out") from `Disconnected` ("watcher thread dropped the
re-arm ack"), so a dead watcher thread reports instantly and honestly
instead of a fabricated 10s "timeout". Observation (3) (unsanitized
picked-path println) deliberately NOT taken: the verifier classed it
with T-001's project-folder line — the local user's own choice, not
repo content — and named no action.

**Frontend seam** (`app/src/lib/watcher-store.ts`, the only app/src
touch): `PickOutcomePayload` union gains `{ kind: "busy" }` and
`pickProjectFolder`'s switch gets an explicit no-change `busy` case.
The store's own `picking` gate makes webview-side Busy near-unreachable
(it exists for OTHER webview contexts / compromised callers — the Rust
latch is the real gate). No new vitest test: this suite has no IPC
mocking machinery (the T-007 verifier's component probe was a
deliberate throwaway), the union is tsc-checked by `npm run build`, and
the wire contract is pinned Rust-side.

### Flags for the verifier
- The pin reads `gen/schemas/*` (gitignored, tauri-build-regenerated).
  `cargo test` always runs build.rs first, so the artifacts are always
  the CURRENT tree's compiled truth — precisely what makes the
  capability-mutation demo end-to-end. If tauri-build somehow did not
  run, the test fails loudly at the unreadable-file panic, never
  silently passes.
- `EXPECTED_GRANTS` is macOS-derived; the manifests are target-filtered
  at build time and resolution uses `Target::current()`, so the Linux
  lane may print a diff → decision filed as T-021-s1 (per-platform
  pins vs normalized projection). The other four acl_pin tests are
  platform-independent.
- Denial-message DETAIL asserts ("dialog:", "Plugin not found",
  "Command not found") are `#[cfg(debug_assertions)]`-gated: release
  builds reject with a terse "not allowed by ACL" string. The core
  "not allowed" assert is unconditional. (`cargo test --release` kept
  in mind by construction; not part of the gate, not run.)
- `pick_project_folder`/`index_repo` could not register on MockRuntime
  (Wry-monomorphic `tauri::AppHandle` — `CommandArg<MockRuntime>`
  unsatisfied). `docs_snapshot` (State-based, runtime-generic) is the
  executing local positive control — the T-007 verifier's own choice;
  the ACL layer treats all app commands identically by construction
  (name-based decision BEFORE handler lookup + `has_app_acl == false`,
  both pinned). Remote-origin denials for all three are probed and
  provably precede dispatch. Filed as T-021-s2.
- PRE-EXISTING race, unchanged in kind by the narrowing, named so
  nobody re-derives it: `project_status` clones the project dir under
  the lock, then takes its seq and collects OUTSIDE it (T-007 shape).
  A `docs_snapshot` that read the OLD dir before a pick's commit can
  take a HIGHER seq than the pick's snapshot and deliver an
  old-project `Open` late; the frontend would reset to the old project
  until the next emit heals it. Under the OLD broad lock the identical
  interleaving existed (status clones-then-releases BEFORE the pick's
  lock acquisition, seq taken after); the narrowing only shrinks how
  long a status call can be DELAYED, never what it can observe out of
  order. Unreachable from the shipped store (`docs_snapshot` is called
  once, at init, before any pick can exist); a compromised webview can
  only confuse its own view, self-healing on the next docs-changed.
  Recorded, not fixed — fixing it means stamping status reads with
  commit-ordering they currently do not need.
- The store's webview-side `picking` guard stays: redundant with the
  Rust latch for serialization, still load-bearing for the disabled
  button state, and defense in depth.
