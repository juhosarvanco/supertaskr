## Specification

A fresh verifier must judge the entire admitted task when product code and private development records live in separate repositories. The original frozen permission and bases remain distinct from the implementation candidates being reviewed. Whole-set preparation, two-spawn review and independently collected evidence preserve actual tested identities and mandatory assigned corrections; actual corrected integration remains T-355's responsibility. No product-side private card, caller manifest or broader mutable registry supplies authority. This is one qualified verification cycle, not general split landing or private-save activation.
