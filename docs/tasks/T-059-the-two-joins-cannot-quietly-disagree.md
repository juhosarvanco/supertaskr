are removed in the same commit as this card.

GATED ON T-033'S ADR-015 RULING (T-014-s1, folded there at this same
triage). If the architect rules that `arch` moves to the Node CLI when
C-02 exists, the Rust join dissolves and so does this card. If the
crate keeps the reality-side join — which is what
`--fail-on undeclared|unmapped` already implies — then it must carry
these refusals and this pin.

T-014's `registry.rs` argues for its own existence this way: "A second
reader is dangerous when it can quietly disagree; this one either
reads the same facts or stops the gate (exit 3)." **That claim is not
exact, and the exception is reproducible.** Re-verified at triage:
`unquote` (`registry.rs:286-294`) strips the surrounding quotes and
returns the interior VERBATIM — it never processes YAML's
double-quoted escapes, and @nputer/parser does. Three input classes
make `nputer-index arch` exit 0 with a confident report that
disagrees with the TypeScript engine about which component owns a
file, and in two of the three the polarity is INVERTED from the one
the notes argue for: the hardened parser refuses and the second reader
guesses.

Not live today — all eleven component files were checked mechanically
and the two engines agree on 252 fact lines byte-for-byte. The
divergence is latent, which is precisely why a pin over the LIVE
registry would never catch it, and why T-014-s6 ranks above T-014-s2.

## Acceptance criteria
- `unquote` SHALL REFUSE rather than guess: if the scalar was quoted
  and its interior contains a backslash, return
  `RegistryError::Malformed` with "quoted escape sequences are not
  supported (refusing to guess)". Do NOT implement YAML escapes —
  that is the fork ADR-015 forbids (T-014-s6, class 1).
- A DUPLICATE top-level key SHALL be refused, not merged. Today
  `get_or_insert_with` merges the second `paths:` block into the
  first (`["nowhere/**", "src/**"]`) and exits 0, while
  @nputer/parser rejects the record and the component vanishes from
  the model (T-014-s6, class 2).
- A TAB-INDENTED list item SHALL be refused. Today a list item
  indented with a tab is accepted (`paths: ["src/**"]`, exit 0) and
  @nputer/parser rejects the record (T-014-s6, class 3).
- EACH refusal SHALL name the file and exit 3, and each SHALL be
  pinned by a fixture that reproduces the divergence BEFORE the fix:
  the emoji-escape case is the sharp one, because both sides
  currently succeed and the gate reds a repo the app draws as clean
  (`verdict DRIFT --fail-on unmapped matched 1 finding(s)`, exit 1,
  against a TypeScript engine reporting no findings at all).
- THE FIXTURES SHALL BE GENERATED, NOT TYPED. Every one of these
  three classes is a byte that is invisible in a diff — a tab, a
  backslash escape, a duplicated key. Build them from character codes
  in the test's own setup and assert the generated bytes, the way
  T-027's branch generated its escape fixture from a character code
  and verified its own output. A hand-typed tab fixture is one
  reformat away from silently becoming spaces.
- ONE assertion SHALL live BESIDE the TypeScript fixture in the app
  lane (`app/test/architecture-dogfood.test.ts`, where the
  expectations already live and already get reconciled): spawn
  `nputer-index arch --root <repo>` and compare its `edge` lines
  against the same `derived.edges` array the fixture already builds.
  ONE reconciliation point instead of two, no new numbers to
  maintain, red the moment either engine moves (T-014-s2).
- THE COST SHALL BE PAID EXPLICITLY: that assertion needs a built
  binary on PATH or a `cargo build -p nputer-index` step, and
  CONVENTIONS already warns that declaring a component moves THREE
  fixtures. The notes SHALL state whether this makes it four, and IF
  the binary is unavailable THEN the test SHALL SKIP LOUDLY naming
  the missing build — never pass silently.
- `tests/arch.rs`'s existing pins (totality, determinism,
  order-independence, the package.path seam) SHALL stay green and
  byte-unchanged.
