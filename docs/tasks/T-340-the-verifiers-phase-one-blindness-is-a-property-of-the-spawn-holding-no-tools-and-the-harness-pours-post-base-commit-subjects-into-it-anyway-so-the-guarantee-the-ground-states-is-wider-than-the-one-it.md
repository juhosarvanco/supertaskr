## The finding

The guarded tier's bench is two spawns, and phase one's worth rests on one claim: it cannot see the diff, the executor's notes, its report, the commit log, or any figure measured after the base. The ground it is handed says so in as many words, under a heading that reads "What must not reach you, and has not."

One half of that is stated everywhere and enforced nowhere, and the card corrected itself on this before filing. The arm's `PHASE1_SPAWN_NOTE` ASKS the seat to "spawn phase 1 tool-less" and the rendered brief TELLS the agent "You hold NO file, git or shell tools" — but an arm cannot spawn a seat, so both are instructions and neither is a restriction. What is measured is narrower: both returns on 2026-09-15 came back having used no tools, and on this session's launch route the spawn carried a tool set it simply did not draw on. ZERO OBSERVED CALLS IS NOT MECHANICAL IMPOSSIBILITY. No tool-less launch route has been demonstrated in this harness, and until one is, "holds no tools" is a request the ground reports as a guarantee. The other half is not the arm's to promise. **The agent harness that runs every subagent in this session injects an environment block carrying recent commit subjects, and it does so before the prompt the arm wrote.** Nothing the dispatch arm does reaches that.

Measured on 2026-09-15, from the two returns themselves rather than from reasoning:

- T-336's phase one read the subject of the seat's own fence-widening commit, which described the criterion it was about to attack: that the guard reports a count rather than an identifier, that it prints only where the verdict is not a success, and that the event is absent from the field set the guard asks for. It marked the two attack lines it could no longer claim as blind and told phase two to discount them.
- T-330's phase one read five subjects newer than its base, learning that a lane was live beside it and that lane's fence had been widened. It reported that this shaped one cross-cutting attack and nothing else.
- T-331's phase one, earlier the same day, disclosed no contamination at all — because that day's recent subjects happened to concern the filing of unrelated cards.

**THAT LAST READING IS THE WORST OF THE THREE.** The leak is not constant: it is a function of what happens to be in the log when a lane is cut. A guarantee that holds on Tuesday and fails on Wednesday, with nothing in either run to distinguish them except a verifier's own honesty, is not a guarantee.

The one mechanism that worked was the role file's requirement that a verifier report the frame it actually had rather than the one the construction promised. Both returns disclosed the leak unprompted, and one of them graded its own work down as a result. Nothing else in the system would have caught it.

And the seat is a participant rather than a bystander: the material contamination came from a commit message written to make the record legible to a later reader. It reached the wrong reader before it reached that one.

## What would settle it

The ground stops claiming what it cannot deliver. It says what is mechanically true — that this spawn holds no tools, and therefore reaches nothing by its own act — and it names the harness's own context as an uncontrolled input rather than asserting that nothing else arrives. A guarantee stated narrowly and truly is worth more than a wide one that a verifier has to correct from the inside.

The frame disclosure stays and is strengthened rather than trimmed, because it is the only thing that caught this. A return that does not say which frame it actually had is incomplete, whatever else it contains.

A seat's commit subject is treated as what it is: a channel into every subagent spawned afterwards. An act on a live lane carries its reason and not its implementation detail, and the convention says so where a seat will read it before writing rather than after.

What this card does NOT attempt: to close the channel. The arm cannot strip what the harness injects, and a card promising that would be promising something no code in this repository can perform. What it can do is stop the ground from overstating, and stop the seat from feeding it.

## Acceptance criteria

- WHEN the arm renders a phase-one ground THE text SHALL state only what the launch route actually enforces, and WHERE no tool restriction is enforced THE text SHALL say that the tool-less pass is a REQUEST to the spawning seat rather than a property of the spawn, and SHALL NOT assert that material from after the base has not reached it by other means.
- WHEN a tool-less launch route is demonstrated on a named harness THE card SHALL record which harness and how the restriction is enforced, and the ground's wording for that route MAY state it as enforced; absent that demonstration the wording SHALL remain the request.
- WHEN the arm renders a phase-one ground THE text SHALL name the harness's own injected context as an input the arm does not control, so a verifier meets it as a known condition rather than as a discovery.
- WHEN a phase-one return is saved THE requirement to report the frame actually held SHALL remain, and a return that does not report it SHALL be handled as incomplete.
- WHEN a phase-one return marks an attack as contaminated THE saved artifact SHALL carry that marking intact, so phase two discounts it rather than crediting it as a blind pre-commitment.
- WHEN a seat commits an act on a live lane THE convention SHALL require the message to carry the act's reason and not the implementation detail of the work under way, and SHALL say why, naming this leak.
- WHEN this card is verified THE tests SHALL exercise a rendered ground and demonstrate that it makes the narrow claim and not the wide one, with a body that reds against the wide wording, the present "You hold NO file, git or shell tools" sentence included.
- WHEN this card is built THE work SHALL NOT reopen verifier-only material to a builder in the course of investigating the harness, and the card SHALL record how that separation was kept.
