# supertaskr — the published command's root

This directory owns the `supertaskr` npm package, its installed entry, and the shared modules used by checkout hooks and project commands. `tools/e2e/` remains the private test package. Nothing here publishes to the registry; publication remains the owner's decision (T-266).

Run `npm ci` and `npm pack` here to build a local tarball. Packing requires Rust and builds this tool's standalone indexer with the locked dependencies. It generates an ignored `dist/` from the runtime scripts, parser sources, method files and the native indexer, then removes that stage. The tarball is for the platform and architecture on which it was packed. The installed commands need no Supertaskr checkout, target-project Rust layout or adjacent parser build. Install it into a project with `npm install /path/to/supertaskr-0.1.0.tgz`, then run `npx supertaskr status --root /path/to/project`.

For a configured split workspace, `supertaskr index --root PRODUCT` checks the private graph against working code. Add `--write` to publish a generated graph through the private-record operation store, or `--watch` to keep it current. Code changes that have not been committed are included and reported as working-source provenance. The graph and component registry live in the associated private records repository; product-side copies are not used. An unchanged committed graph produces no new private commit or file replacement. `supertaskr arch --root PRODUCT` reads that graph and registry; its `drift`, `cycles` and `blast` forms use the same homes.

An interrupted update retains its original operation. A normal update reconciles a matching pending operation first; `index --recover` lists original operation metadata and `index --resume ID` explicitly resumes one. A running watcher retains its original physical homes and reports a changed association instead of following another records repository. Graph publication runs no product suite, build, push or CI job. It does not publish a remote.

The command still refuses verbs whose implementation has no project-root argument when the package and project differ. General configured-gate operation belongs to T-303; packaging does not claim that outcome. Checkout hook adapters continue importing these shared owners without an installation or build.
